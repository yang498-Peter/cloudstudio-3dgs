# 2026-08-25 清晰度攻关：验收体系的盲区与致密化落点

用户反馈渲染模糊、边缘不清、与照片差距大。本轮从"加指标"开始，最后把原因收敛到致密化的落点上，并换成开源参考实现。

**先说结论**：画质本身尚未实质改善，最好的模型仍在一致性 0.339（照片为 1.0）。但排除掉的每一条都有单变量测量支撑，且找到了一条有因果链的主线。

## 一、根本问题：五表验收看不见"糊"

PSNR / SSIM / LPIPS / 深度 MAE / 漂浮物——**五项全是全帧平均**。砾石糊成一片米色对它们的影响，和均匀降一点对比度差不多。所以整套体系可以一路显示"在进步"，而画面始终是糊的。

这不是假设。D1 实验给出了最刺眼的证据：**同一配置只打开致密化，PSNR 从 15.459 涨到 15.565，与照片的结构相关性却从 0.339 掉到 0.291。** 我们优化的指标和要解决的问题是反向的。此前那个"五表全破纪录"的 C6，是在错误的坡上爬到了顶。

## 二、补上的三个指标

新增 `tools/sharpness_metrics.py`，三项一起看（照片为 1.0 / 1.0 / 0%）：

| 指标 | 回答什么 | 单独看的陷阱 |
|---|---|---|
| **能量比** | 细节量够不够（渲染高频 ÷ 照片高频） | 分不清"锐利"和"噪点" |
| **梯度一致性** | 细节位置对不对（两张梯度图的相关系数） | 模糊模型天然占便宜 |
| **覆盖率** | 有多少像素根本没有高斯 | 缩小高斯可以用窟窿换锐度 |

后两个都是被具体的误判逼出来的：

- **一致性**：G3 的能量冲到 0.829（四倍于其他臂），我一度判为突破。加上一致性才看清它只有 0.180，全场最低——**大部分新增高频与场景无关，是画出来的**。
- **覆盖率**：用户指出渲染图里的白色条纹是缺高斯、透出背景。量化后 G3 有 **14.9% 的像素完全没有高斯**。洞的边缘是硬边，会同时抬高能量、压低一致性——我把覆盖率崩溃误读成了纹理造假。**没有覆盖率的锐度数字会骗人。**

另新增 `tools/gaussian_scale_audit.py`（测最长轴）和 `tools/pose_reprojection_audit.py`（不依赖 hloc 的位姿误差测量）。

## 三、逐条排除（全部单变量）

| 假设 | 测量 | 结论 |
|---|---|---|
| 高斯数量不够 | 39万 vs 200万 | **排除**：能量都是 0.199 |
| 泛化/过拟合 | 训练视图本身 | **排除**：只有 0.22-0.35，连见过的图都还原不了 |
| 渲染路径 | 针孔面 0.211 vs 鱼眼 0.271 | **排除**：两条路一样糊 |
| 几何正则压平外观 | V4 全关 | **排除**：反而降到 0.132，正则在帮忙 |
| 高斯太大 | 尺度审计 | **部分成立**，见下 |
| 相机轨迹误差 | 跑通 BA | **排除**：BA 自身残差 −34.7%，画面问题依旧 |
| 相机-LiDAR 外参 | 结构测试 | **排除**：全局平移 <1px，无刚性错位可修 |
| LiDAR 两种用法失衡 | V1/V2 | **排除**：两项都是净正，平面项贡献是深度项的 2.3 倍 |

### 尺度：找对了方向，但不能单独用

法线正则把**最短轴**从 3.45cm 压到 1.23cm，**最长轴 8.49→8.47cm 纹丝不动**。高斯变成了又薄又宽的煎饼——几何指标理想（墙厚、贴合角、漂浮物**测的都是最短轴**），光度上是一片抹平。57% 的可见高斯投影宽度超过 5px，而砾石石子就是 5px。

`geometry_regularization` 在本轮所有配置里都是 `enabled: false`，而 MCMC 只 relocate 不 split，所以**没有任何环节在限制高斯尺寸**。

但压小它有代价：覆盖面积 ∝ N·r²，G2（5cm 硬钳位）能量升到 0.226 但覆盖率从 3% 恶化到 10%，G3 更紧则到 15%。**尺寸和数量必须一起调。**

### 位姿：两条独立证据都指向"修不了"

- BA 跑通并被接受（先验 0.01m，重投影 1.604→1.047px，尺度漂移 0.18% 过关），但独立复测显示与 LiDAR 的偏移**没有改善**（7.27→7.41px）。机制在源码里：`report.py` 对三个 stage 硬编码 `refine_sensor_from_rig=False`。
- 结构测试进一步否定外参假说：全局平移 <1px 而帧间散射 2.7-3.0px，**刚性外参求解最多拿回不到 1 像素**。

用户指出该 LiDAR 精度 2-3cm、斜入射更差，是**平面参考**而非逐点真值。2-3cm 在 3-5 米处正好对应 4.7-7.8px，覆盖了实测散射，且配准误差局部相关，这解释了 0.43 的帧内一致性。**残差是设备精度极限，不是可标定的系统误差。**

## 四、主线：致密化的落点

### 现象

按一致性排序，**唯一不做致密化的 S0 是最高的**，所有会长新高斯的配置都更差，且越激进越差：

```
S0（不生新高斯）  0.339
G2                0.298
V2                0.293
V1                0.260
V4                0.239
G3（压得最狠）    0.180
```

这个模式一直在数据里，我用能量和 PSNR 排序时看不见。

### 单变量确认（D1）

S0 的配置，**只**打开致密化，其他一字未改：一致性 **0.339 → 0.291（−0.048）**，PSNR 反而上升。

### 原因（判据分歧测量）

这个测量本来是设计来**枪毙后续想法**的——如果新旧判据选中同样的像素，换了也白换：

```
两张图相关性        0.189
致密化作用区重叠     22%      → 78% 的位置指向不同
分歧处照片纹理强度：
  只有旧判据选中     0.037
  只有新判据选中     0.15-0.19  → 高 4 倍
```

**现在的致密化把高斯放在照片纹理只有四分之一的地方。** 图像误差标记的是"模型错在哪"，而遮挡、反光、曝光差异都会产生大误差却没有任何结构。

## 五、修法：换成开源参考实现

用户明确要求参考成熟开源方案而非自创。查证后：

| 方法 | 出生判据 |
|---|---|
| 经典 3DGS (Kerbl) | **视空间位置梯度** `∂L/∂μ_2D`，阈值相对场景尺度；配 opacity reset 清漂浮物 |
| 3DGS-MCMC | 按不透明度采样，**不用误差图** |
| AbsGS / Pixel-GS | 修梯度符号抵消、大高斯不分裂 |
| 本仓库 | **图像误差加权 MCMC —— 自创偏离** |

原版判据没有我们的失效模式：平坦区域的曝光偏差产生颜色误差，但**不会把高斯往旁边拉**。

gsplat 1.5.3 自带 `DefaultStrategy`，参数就是原论文的。新增 `default_strategy_adapter.py` 让它以现有代码期望的接口接入，MCMC 路径不动（原 72 个测试全过）。

**一处会静默失效的接线**：`step_pre_backward` 在 MCMC 下是空操作，但在原版下**它才是保留 means2d 梯度的地方**，而这个钩子此前从未被调用。漏掉不报错，判据只是永不触发。已走 backend 统一分发并单独测试。

## 六、四次失败重启，以及一次我自己的错误应对

A/B 接线暴露了四个问题，值得逐条记录：

1. **数量守卫**：遥测层断言"refine 不减少高斯数"。这对 MCMC 是真不变量，对会 prune 的经典致密化是误伤。**改成由调用方声明语义，没有放宽守卫。**
2. **absgrad 通道**：AbsGS 读 `info["means2d"].absgrad`，光栅化器只在被要求时累积。已按策略需要精确开启。
3. **opacity reset 兼容**：原版每 3000 步把所有不透明度压低，渲染短暂为空，而深度损失是 fail-closed 的，在 step 3000 精确抛异常。
4. **我的错误应对**：我关掉了 opacity reset 来绕过第 3 条，理由是"它是独立辅助机制"。**这个判断是错的**——漂浮物随即单调涨到 6206，比对照臂高一个数量级，因为 reset 正是清漂浮物的机制。那个臂测的已经不是原版方法。

第 4 条的正确修法是拆开损失函数里混在一起的两种情况：**监督端为空**（数据坏了，保持致命）与**预测端为空**（训练瞬态，返回挂在计算图上的零）。修好后 reset 可以正常运行。

四次都是**显式报错**而非静默降级。如果 absgrad 那次只是判据永不触发，我会拿着"absgrad 没用"的假结论汇报。

## 七、方法论：先设计能证伪它的测量

本轮三次在动手前用测量决定要不要做，**两次叫停**：

| 想法 | 预先测量 | 结果 |
|---|---|---|
| 尺度正则能压小高斯 | 尺度审计 | 最长轴反涨到 16.37cm，**反效果** |
| 六自由度外参求解 | 结构测试 | 全局平移 <1px，**不值得写** |
| 结构感知出生判据 | 判据分歧 | 重叠仅 22%，**值得做** |

G1 那次尤其说明问题：只看锐度下降会得出"尺度控制没用"，是审计当场显示最长轴翻倍，真相才是"这个控制把高斯养大了"。
