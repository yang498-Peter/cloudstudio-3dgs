## 二、根因排序（已确认 = 代码行 + 遥测/检查点复算一致；假设 = 机制成立但影响量未测）

### R-A【已确认，P0】监督信号被深度噪声主导，RGB 只占总 loss 的 9%

- 我方总 loss 中 LiDAR range 项占 62–71%、DA2 占 18–27%、RGB（L1+DSSIM）约 9%（h5v 遥测 928 步复算，range 项在 73% 的步是最大加权项）。
- range 项是 **0.5 × 线性米制 L1**，而训练器自身默认是 **0.05 × robust log-Huber**（trainer.py 默认值），切片配置在 3a06caa 静默覆盖，无任何记录理由。
- 它永远拟合不上：range L1 分窗中位数从 2.7 m 到 3.8 m 全程不降。原因在数据侧：**face4 LiDAR 缓存没有遮挡剔除**，Tile_0 有 57% 的 LiDAR 监督像素落在可见表面之后（穿墙点、树冠后的点）；参考交付件对同一批目标打出 4.86 m MAE，说明目标本身不可拟合。
- 致密化梯度源是 total_loss，所以这份噪声还决定了克隆在哪里出生。
- 参考配方（逆向恢复）没有稀疏 LiDAR range 项，深度监督走近全像素 DA2/mesh 且在有界压缩空间。
- DA2 项自身也有缺陷（P2）：mono_depth_mask 没有远距截断，对齐后的天空目标达到千米量级（fp16 上限），线性 L1 让 da2 loss 中位 2.6 m、最大 116 m。

### R-B【已确认，P0】opacity 体制反了：只有向上推力，没有向下排水

- 我方 alpha 地板（weight 0.5、target 0.95、6 px 膨胀）覆盖 76–95% 的掩膜像素，**包括枝叶之间的天空**，是单向 relu(0.95−α)² 的推力；参考配方里没有这一项。
- 除 reset 外没有任何向下的力：opacity_sparsity 0、scale_upper 0，各向异性/切向/压平只作用于轴比。
- 结果：每个 reset 周期内均值 opacity 单调上升 0.31→0.63，三分之一高斯超过 0.9；reset 钳到 0.2 后 100 步的 immediate cull 一次清掉 35–36%（3101/6101/9101 三次实测），形成锯齿。参考人口在 0.05 硬地板之上单调递减，p50 0.197，只有 2% 超过 0.9。
- 树冠"白絮"的直接机制就在这里：地板把枝间天空排到 α≥0.95，唯一同时满足地板和照片的解是天空色的不透明高斯（APP-1）。
- 复核员的修正：仅加 0.01 的 mean-opacity 正则在当前体制下不够，地板才是主驱动；所以阶梯先撤地板，再加排水。

### R-C【已确认，P0】没有任何缩小算子，克隆偏向大而不透明的父本

- split 在构造上不可达：split 门槛 0.2 m 与 world shrink 上限 0.2 m 同值，173 次 refine 事件 split 恒 0（h5v/resetA/resetB 全部）。
- clone 是逐位复制：子代出生在父本原位，Adam 状态清零；means lr 1.6e-5（绝对米制，无场景尺度乘子）每步最多 0.01 mm，一个周期内分不开。7434 步时 61% 高斯与另一个共享 1 mm 格，中心最近邻 p50 0.44 mm，而长轴 18.9 mm——**用堆叠而不是铺展来覆盖**。
- clone 的选择有尺寸偏置：可克隆父本长轴 p50 29.5 mm（人口 18.9）、opacity p50 0.91（人口 0.66）。3.6 次人口周转后长轴被棘轮式推高。
- 压平项在 tangent_ratio 模式下的分母不 detach，梯度同时压短轴、**拉长切向轴**；参考自身厚度比 0.18，我方目标 0.1 是过度压薄。
- 参考的长轴 4.41 mm 恰好 = 初始化 7.07 mm ÷ 1.6，即一代 split 的结果；参考最近邻 1.5–2.7 mm。
- 可走的路：detail split 策略（校验器钉死 0.02 m / 0.0035 屏幕半径、revised_opacity 必须为 true），7434 步时 47.5% 的高斯长轴超过 0.02 m，split 分支第一次有父本可用。

### R-D【已测量，未复核】切片外监督泄漏

- 裁剪矩形只按像素裁，不按切片归属掩膜：Tile_0 有 33% 的 LiDAR 监督像素（Tile_1 63%、Tile_2 48%）的三维点在切片盒之外，那里没有高斯、背景是白色，RGB/range/alpha/DA2 目标在构造上不可满足；唯一能降低 loss 的自由度是盒内高斯沿射线长大变实。
- 后果是切片边界的"墙"：盒边 0.2 m 带内长轴 p50 130 mm、opacity 0.94，合并时又被 core-owner 丢掉。

### R-E【已测量，未复核】评测口径

- 原 48 视角电池全部在 Tile_1 内（时间块 0），不能给 Tile_0 打分；包含天空；朝下视角背景纯白且 LiDAR 支撑 0.09%。
- 本次已加 `--tile-views`（切片自己的裁剪训练视角）和前景掩膜/分面统计，作为切片级 A/B 的判据；它是训练视角分数，必须如实标注。真正的保留集需要空间分块划分，属于下一次数据集重建。

### 被复核推翻或降级的

- "init opacity 0.1 落在 cull 门上导致第 500 步砍掉 55%"：数字属实，但改成 0.2 不改变均衡（cull 是持续流，不是一次性事件）。
- "reset+100 冲刷占每周期死亡的 70–78%"：实测只占 21–26%，稳态 cull 才是大头。
- "停点落在冲刷谷底是 P0"：对 P10 无影响（见上表）。
- "期望深度 vs 中值深度导致长轴拉伸"（LOSS-04）：机制未测量，撤回。
- "加 0.01 mean-opacity 正则能把 opacity 拉回参考"：在地板未撤时无效。

## 三、实验谱系（显式血统；每臂 3,500 步 = 一个完整 reset 周期 + 冲刷 + 400 步恢复；以 `ladder_lineage.json` 为准）

```
h5v
└─ R1 range 0.05 robust
   ├─ R2 去 alpha 地板                       [判负：alpha P05 −0.09，opacity 不动]
   └─ R3 adaptive-detail split，地板保留      [胜]
      ├─ R3B 去 alpha 地板                   [交互检查：P10 +0.1，覆盖塌]
      ├─ R4 flatten 绝对 1 mm                [判负：短轴 1.14→3.33 mm]
      └─ R5 统一 0.05 cull                   [胜；R5r 为显式血统下的复现]
         ├─ R6 opacity 排水 0.01             [判负：人口减半、alpha P05 −0.1]
         ├─ C1 切片归属掩膜                   [监督正确性]
         ├─ C2 DA2 远距截断 + 压缩空间        [监督正确性]
         ├─ C3 隐藏点剔除 LiDAR 缓存          [监督正确性，缓存已重建：train 剔 52%]
         │  └─ C4 = C3 + C1 + C2             [正确性合集]
         ├─ T1 split 门 10 mm / T2 5 mm      [尺寸机制；将改挂到 C3/C4 赢家之下]
         └─ S1 尺寸铰链（中位初始尺寸 2 倍）   [尺寸机制；同上]
```

执行顺序：C1 → C2 → C3 → C4 → R5r；C3/C4 定出赢家后，T1/T2/S1 从赢家重新派生再跑（不在脏监督上比尺寸）。每臂产出：形态六指标、切片级电池（P10、alpha P05、前景 P10）、3101 冲刷比例、split 血统（父本/子代 opacity 与尺寸按年龄分桶、人口增速）。5 mm 门一旦出现人口爆炸或离面人口上升即停。

**不开 20 epoch 长跑**：血统探针已证明 20 mm 门下多跑代数不会让尺寸穿过 12–20 mm 平台，长训只是在这一层做人口交换。

**审稿修正（2026-09-02 下午）**：第一版 stager 是累积 mutate，被判负的臂会隐式带进后面的臂；已改为显式血统（每臂声明 base + 单一改动，`ladder_lineage.json` 记录 base 与配置 sha，运行目录保存 `config_as_run.json`）。按实际运行的遥测核对：上表 R3 的确是"R1 + split、alpha 地板保留"（遥测里 alpha loss 存在），R5 是"R3 + cull 0.05、flatten 仍为 tangent_ratio"，R6 是"R5 + 排水 0.01"；只有 R6_A 是混合臂（带 flatten 绝对模式）并已如此标注。补做 R3B（R3 去 alpha 地板）回答 R2 与 split 的交互。

**结论措辞修正**：R2 的单变量证据只说明 alpha 地板撑住了覆盖（alpha P05 −0.09）而 opacity 分布未动，**不能**说地板是 opacity 饱和的主驱动；它确定的问题是污染覆盖语义（枝间天空被排成不透明）。R3 的 split 是 CloudStudio 自己的 adaptive-detail split（0.02 m 屏幕半径门），不是参考配方的复刻，参考的 type-2 路径是 clone 为主、世界尺度大才 split。

**过程事故**：detail split 强制的 revised_opacity 在库函数里对饱和到 1.0 的父本给出 +inf logit，两条探针分别在 2800/2900 步被 fail-closed 拦下；已在适配器侧夹紧修复（03ca89e），带回归测试。

### R3B 与血统探针（2026-09-02 下午）

R3B = R3 去 alpha 地板：PSNR 16.76（R3 17.11）、P10 12.86（12.76）、alpha 均值 0.701（0.885）、alpha P05 0.382（0.517）、opacity p50 0.557（不变）、长轴 p95 35.5 mm（55.2）。结论：地板不驱动 opacity 饱和（两次单变量都不动），但它撑住覆盖和均值，同时把长轴尾部吹大、把 P10 尾部（树冠/天空视角）压低 0.1 dB。保留地板，后续用"天空掩膜排除地板 + 缩小膨胀半径"去争这 0.1 dB，而不是整个撤掉。

split 父本的 opacity 从第 501 步的 p50 0.29 一路升到 2900 步的 0.93（>0.9 占 58%），reset 后回落再爬升；子代出生后 opacity 随年龄回落到人口水平，没有停在 0.999——数值修复之外没有"饱和子代"堆积。**真正的问题是尺寸**：split 子代出生时就 18–19 mm（父本 30–45 mm ÷ 1.6），之后不再变小，而校验器把 detail split 门钉在 20 mm，18 mm 的子代永远不再分裂。人口长轴中位数被 12–20 mm 这一层锁住，与"更多代数自然变锐"的假设相反。参考的 4.4 mm = 初始化 7 mm 一代 split，参考从没让高斯长到 30 mm。

因此新增三臂（叠在 R5 上）：T1/T2 把 detail split 门放到 10 mm / 5 mm（校验器与 gate 改为接受 {0.02, 0.01, 0.005}）；S1 在中位初始尺寸的 2 倍处加尺寸铰链（scale_upper 0.01、ratio 2）直接对抗长大。

- 全用的工程路径：split 构建器与 tile plan 构建器都 fail-closed 要求 val 非空（`validation_fraction ∈ (0,1)`、`--val-face-manifest` 必填），最小合法 val 是 1 个 rig 帧（2 张）。方案：新 split（val = 1 帧）→ 重建 face4（884 张）→ renderer mask → LiDAR 几何 → DA2 → tile plan / tile inputs → ownership → tile gate → 烟测 → promote → 绑 DA2 → 背景。4 张无位姿图需要照片注册（独立任务），不是剔除而是暂时做不到。
- **天空层一直有**：训练用 `probes/sky_house0305.pt` 预烘焙照片穹顶（10 万高斯，半径约 250 m）作背景，交付应当作为独立 PLY 与主体一起给，与竞品 `sky.ply` 同构。F5 链漏了这一步，已补出 `exports/house0305_f5_sky_20260903.ply`（6.8 MB）。以后交付链必须两件套。
- **悬浮体实测**（活跃高斯 opacity>0.1 到 LiDAR 面的距离，同一 LiDAR 面、参考经对齐残差 1.4 cm）：我方 >0.2 m 占 6.6%、>0.5 m 占 2.5%、>1 m 占 0.8%；参考 3.4% / 1.3% / 0.7%。**我方离面悬浮比例约为参考的 2 倍**（绝对数相近：>0.5 m 我方 19.0 万，参考 22.5 万）。小白点（rgb>0.85、<1 cm）我方占活跃 6.1%、参考 20.9%（参考的白点在金属天花板和白墙上，是贴面的）；离面 >0.2 m 的小白点我方 2,008、参考 2,800。结论：悬浮体是真实差距但不是数量级差距；离面 0.2–0.5 m 这一层是我方多出来的，对应 LiDAR 项在遮挡穿透处的错误目标与树冠无地板区。

## 六、优先级重排（2026-09-02 傍晚，按第三轮审稿）

- **门的案例（2026-09-02 晚）**：室内帧里那扇关着的白门渲染成半透明糊。LiDAR 深度图在门的位置看到的是门后 4.7 m 的树——扫描时门是开的，照片里是关的；初始化在门的位置没有点，稀疏 range 项把高斯往 4.7 m 拉，光度项要在 1.5 m 画门，两者打架。参考配方没有稀疏 LiDAR range 项，所以它跟着照片。长跑修不好这类"扫描时的动态物体"，只有去掉/门控稀疏 range 项才能修：新增 C5（C2 + range 权重 0）与 C5h。C3 的隐藏点剔除对此无效（门在 LAS 里根本不存在）。

## 六之一、当前判断（2026-09-02 中午）

- 路线清晰：四个根因都有单变量证据，阶梯上每一级的方向都能被电池和形态数字解释，没有"玄学"项。
- 距参考的剩余差距：P10 0.5 dB；长轴中位数 3 倍（13.5 vs 4.4 mm）；短轴 2.6 倍（1.14 vs 0.43）。前者靠更多 split 代数（满长 20 epoch 才有 8 个 reset 周期），后两者靠 R5/R6 的 opacity 排水让克隆不再堆叠、以及 flatten 比例目标的再标定。
- 已越过参考的：均值 PSNR、alpha 均值、alpha P05、长轴 p95。
- 不做的事：现在不开 20 epoch 长跑。理由有三：切片电池是训练视角分数，"均值 PSNR 超过参考"只说明拟合训练视角更好；R3 的 opacity 仍饱和（p50 0.56、>0.9 占 15%），split 子代继承饱和父本的 opacity（数值上已夹紧到 0.999999，但那是防崩溃不是画质），更多 split 代数可能制造更多近乎全不透明的子代而不是更锐；57% 遮挡穿透 LiDAR 目标与 33–63% 切片外监督仍在决定致密化的出生地。
- 顺序改为：C0 监督正确性（隐藏点剔除重建缓存、切片归属掩膜、DA2 远距有效性）→ 在可信目标上再做 loss 权重 → 拓扑（split/clone）→ opacity/cull → 形状正则。
- 长跑前必须有的证据：split 父本/子代 opacity 分布与血统（出生步、出生方式、300 步后的 opacity/尺寸）、以及最优短臂延长到 7k/10k 时 P10、alpha P05、长短轴、离群体都继续向参考收敛。
