# 3DGS 训练流程全面审视与优化（2026-11-16）

范围：house0305 上的现行最佳配方 `b12op05d3`（SDK 配置档同名）及其训练器、流水线、SDK。
方法：先用已有检查点做只读测量（不重训），再改代码，最后用切片 1 做对照训练。
所有读数都给出口径；没有测量支撑的判断标为"推断"。

## 1. 结论

1. **位姿、时间同步不是瓶颈。** 用训练好的切片 3 渲染它自己的 300 个训练视角，与照片做分块相位相关：
   逐视角残余错位中位 0.66 切面像素（约 0.016°），旋转光流回归出的残余时间偏移 +1.3 ms，只解释 1.37 px 中的 0.28 px。
2. **约 60 个历史臂的训练视角 PSNR 全部停在 19–20 dB。** 容量 330 万到 1500 万、重置周期 300/3000、SH0/SH1、
   不透明度上限、MCMC/默认增密都只移动 ±0.5 dB。配方旋钮不是约束所在。
   把位置学习率提高 10 倍续训 2900 步，成对视角 PSNR 只变 +0.06 到 +0.20 dB：几何被 LiDAR 冻结这一假设不成立。
3. **训练视角误差的构成**（切片 3，150 视角，监督像素内）：L1 0.096；
   逐视角逐通道仿射可消 14%（照片 ≈ 0.9×渲染 + 0.065，标量增益表达不了偏置）；
   再加一个平滑亮度场可消 18%；剩下 68% 是缺失的细节，量级相当于把照片做 σ=8–16 像素的模糊。
4. **监督图是插值放大的。** 鱼眼轴上角分辨率 787.6 px/弧度；Face4 的俯仰面按 2308.9 px 焦距存储（2.93 倍），
   偏航面 1039.7 px（1.32 倍）。俯仰面照片 98.9% 的谱能量在传感器奈奎斯特频率以下，
   其余是逐张不同的去马赛克/压缩纹理。
5. **客户查看器是经典光栅化，而配方自 b7 起用抗锯齿模式训练。** 抗锯齿训练允许亚像素厚度的高斯存在
   （训练时被降亮），经典查看器按全亮度画出来就是针。我们的最薄轴中位 0.26–0.29 mm，
   折合最近相机处 0.15 个传感器像素，40% 低于 0.1 像素；竞品中位 0.20–0.27 像素，低于 0.1 像素的只有 17–22%。
   `max_opacity 0.5` 是用雾化来遮针，代价是交付锐度从 0.795（b8，高于竞品 0.574）降到 0.396。
6. **容量在前 2000 步被花完。** 切片 3 的种群在前 15 次增殖里从 565 万涨到 1350 万，此后 2.8 万步一直顶着上限；
   全部容量由"每个视角还没看过第二遍"时的梯度分配。竞品的长轴 p95 是 55.8 mm，我们 26.5 mm：
   它在平坦处用大高斯、细节处用小高斯，我们是均匀的小高斯，另有 42% 的高斯不透明度低于 0.1（竞品 18%）。
7. **单步时间的 60% 花在一个正则项上。** 1450 万高斯时一步 368 ms，其中渲染 17 ms；
   LiDAR 法线对齐项每步对全部高斯做稠密计算：前向 77 ms、反向约 96 ms、占 3.9 GiB 显存。

## 2. 画质：测量细节

### 2.1 配准

| 量 | 读数 | 口径 |
| --- | --- | --- |
| 逐视角残余错位（中位 / RMS / p90） | 0.66 / 1.94 / 3.37 px | 切面像素；俯仰面 1 px = 0.025° |
| 俯仰向下面（近地面） | RMS 0.42–0.59 px | 最好 |
| 俯仰向上面（树冠、屋檐） | RMS 2.5 px，偏置约 1 px | 最差；含风动与细枝 |
| 残余时间偏移 | +1.28 ms，相关 0.19 | 逐视角错位对旋转光流回归 |
| 采集 | 886 张鱼眼 / 443 个机位，帧间隔 0.5 s，速度中位 0.52 m/s，角速度中位 9.3°/s | 数据集清单 |

机位只有 443 个，是稀疏视角场景：少视角能拟合得很锐（单视角 38 dB、5 视角 24–29 dB），
视角多了以后需要的表面纹理总量超过容量，PSNR 随视角数单调下降到 19–20 dB。

### 2.2 误差分解

| 修正到哪一步 | L1 中位 | PSNR 中位 |
| --- | --- | --- |
| 训练时实际比较的（含逐图标量增益） | 0.096 | 18.1 dB |
| 再做逐视角逐通道仿射 | 0.082 | 19.1 dB |
| 再乘一个 σ=48 px 的平滑增益场 | 0.065 | 21.0 dB |
| 照片对自身 σ=4 / 8 / 16 px 模糊（标尺） | 0.044 / 0.062 / 0.071 | — |

同一张照片在不同切片学到的增益极差中位 0.177（对数），与这里的"平滑场"是同一件事：
一张照片内部的亮度相对模型就不是常数（渐晕、相机局部色调映射、耀光）。

### 2.3 厚度与像素足迹

短轴以"最近相机处的传感器像素"为单位（短轴 × 787.6 / 距离，距离 0.3–6 m、不透明度 > 0.05）：

| | p10 | p25 | p50 | 低于 0.1 px | 低于 0.447 px | 长短轴比 p50 |
| --- | --- | --- | --- | --- | --- | --- |
| 我方切片 1（b12op05d3） | 0.026 | 0.051 | 0.152 | 40.1% | 80.5% | 21.8 |
| 竞品，同一包围盒 | 0.070 | 0.131 | 0.269 | 17.5% | 66.6% | 11.5 |
| 竞品，全场景 | 0.063 | 0.110 | 0.202 | 21.9% | 78.9% | 10.0 |

Mip-Splatting（Yu 等，CVPR 2024，5.1 节）给出的三维下界是方差 0.2 px²，即 0.447 px。
竞品没有执行这么强的硬下界，但它的薄尾比我们厚 2–3 倍。

## 3. 速度与资源

切片 3，1450 万高斯，从 30k 检查点续跑、同步计时 60 步：

| 配置 | 每步 | 峰值显存 |
| --- | --- | --- |
| 原样（当时的运行记录） | 368 ms | 10.7 GiB |
| 多线程预解码 + 紧凑上传 | 322 ms | 10.8 GiB |
| + 传感器分辨率监督 | 288 ms | 10.2 GiB |
| + 法线项只算可见高斯 | 153 ms | 8.4 GiB |
| （对照：完全关掉法线项） | 138 ms | 6.4 GiB |

另有两处不在上表里的开销：

* 每次增殖事件后，法线锚点用 CPU KD 树对全部高斯重新查询，切片 1（870 万）上一次 3–8 s，
  一轮 205 次。改为锚点随种群一起经过增殖事件（放进策略状态，由 gsplat 的复制/分裂/删除一并变换），
  每 500 步的周期性刷新保留。
* 背景图 PNG 在训练线程上解码、图像以 float32 过总线。改为在预取线程解码、以 uint8 上传后在显卡上展宽，数值相同。

## 4. 改了什么

全部默认关闭；关闭时不进入合同，历史臂的合同字节不变。启用任一项即是新臂。

| 项 | 配置键 | 作用 |
| --- | --- | --- |
| 法线项作用域 | `lidar_normal_alignment.scope = visible_current_view` | 只对当前视角光栅化到的高斯计算；加权均值在被计算的行上取，平均每步的拉力不变 |
| 锚点随增殖事件传递 | `lidar_normal_alignment.carry_through_refine` | 免去每次增殖后的全量 KD 树查询 |
| 传感器分辨率监督 | `training_focal_px = "sensor"` | 每个面按面积平均降到鱼眼轴上焦距；掩码、稀疏 LiDAR、单目深度、天空标签、内参、各像素半径一起降 |
| 多线程预解码 | `prefetch_workers` | 提前解码后续 2×N 步，含背景图；按步序交还 |
| 容量斜坡 | `default_strategy.capacity_ramp_end_step` | 每次增殖只允许种群到 `初始 ×（上限/初始）^进度`，名额给梯度最高的候选 |
| 采样率下界 | `geometry_regularization.min_extent_px` | 每轴不小于 `min_extent_px × 深度 / 焦距`（取光栅化过它的最近视角）；参数原位钳制，导出无需烘焙 |
| 日程随视角数缩放 | 配置档 `tiling.schedule_scaling` | 实测视角数范围内不变；之外按视角数比例缩放，小切片不再配置失败 |

## 6. 没有解决的

* 逐视角仿射与视角内亮度场（合计 32% 的训练视角 L1）没有建模。代码里有 PPISP 的移植但从未在正式配方里启用，
  启用它需要同时改合并阶段的曝光统一。
* 交付文件 3460 万高斯，高于 2000 万的产品门槛；本次没有动容量上限。
* 大数据集（house0614：每切片 4.6k–7.2k 视角）上日程最多拉长到 2 倍，是成本上限而不是测量结果。
* 没有在第二个数据集上端到端跑过；磁盘可用 54 GB，UK 全流程需要约 153 GB。
