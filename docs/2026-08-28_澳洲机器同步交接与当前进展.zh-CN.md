# 澳洲机器同步交接与当前进展（2026-08-28）

## 1. 这次同步的目的

本次同步不是只推送训练器源码，而是把以下内容一起送入 GitHub，供澳洲机器直接接续：

- 当前可复现的 MVP S1 鱼眼 + LiDAR 3DGS 代码；
- MipMap 竞品静态/动态研究结论；
- snow 数据的时间同步、AT、Face4、分块、初始化、训练和质量审计记录；
- 测试、门禁、失败实验和明确的证据边界；
- 下一台机器的环境准备、验证顺序和继续工作入口。

大型照片、LAS、深度 NPZ、PLY、checkpoint 和训练输出不会进入 Git。它们需要通过数据盘另行复制，并使用 Manifest/SHA 验证身份。

## 2. 当前总判断

当前项目已经从“能跑一个 3DGS demo”推进到“上游数据与 LiDAR 原生训练合同基本成形”，但仍不应直接启动正式长训练。

已经确认的主路线是：

```text
原始双鱼眼照片 + POS + 完整 LAS
  -> 时间同步与输入验签
  -> 342 张原始鱼眼上的遮罩 AT
  -> 共享 KB4 内参 + 342 个独立相机位姿
  -> 1368 个 Face4 训练视图
  -> LiDAR KNN/PCA 表面初始化
  -> LiDAR/照片负载联合空间分块
  -> 每块串行训练和显存释放
  -> LiDAR 表面约束下的颜色、透明度、尺度与有限几何优化
  -> core/halo 裁剪与合并
  -> 独立天空层和最终 PLY/SOG 输出
```

当前正式路线不把 DA2 单目深度、全场景 mesh depth 或局部 mesh 当作前置条件。它们保留为后续 A/B 项；只有 LiDAR 主导基线结果不足时才重新评估。

## 3. 已完成的关键工作

### 3.1 时间同步和输入身份

- snow 数据的照片/POS/LAS 时间戳审计没有发现需要整体平移的证据，扫描最优偏移为 0 ms。
- 数据、掩膜、split、深度、初始化和训练配置使用签名 Manifest 绑定，避免不同 AT、不同照片集合或旧缓存被静默混用。
- 相关入口：
  - `cloudstudio_3dgs/evaluation/time_sync.py`
  - `tools/audit_camera_time_sync.py`
  - `cloudstudio_3dgs/data/manifest.py`

### 3.2 AT 和 Face4

- AT 在 342 张原始鱼眼上进行，Face4 只作为训练视图，不参与自由 BA。
- 当前实现支持两组共享单焦距 KB4 内参、逐图独立位姿和 POS 先验。
- 当前 snow 对比结果与竞品同量级，但不是数值完全相同；不能把“我方 POS 修正更小”直接解释为更准。
- 相关入口：

### 3.3 LiDAR 表面初始化

- 初始化尺度按邻域真实距离估计，不再使用过薄的旧雪面短轴经验值。
- 已实现 KNN/PCA 法线、各向异性尺度、法向到四元数方向、LiDAR 表面切平面 proposal 和新生高斯表面准入能力。
- MipMap 静态审计恢复的参考公式为：K=7（排除自身后的 6 邻点距离算术平均），线性三轴尺度约 `[d,d,0.5d]`；K=30 PCA 法线决定最短轴方向。
- 相关入口：

### 3.5 分块、训练视图和显存合同

- 已实现按 LiDAR 空间分布、预计高斯数和视图负载联合生成 Tile 的基础设施。
- 训练视图带明确 crop，主点随裁剪窗口移动；不再把整张 Face4 无差别送进每个 Tile。
- Tile 采用串行训练和显式 CUDA cache 释放，不依赖多块同时驻留显存。

### 3.6 训练合同和 Gaussian 生命周期

- 训练器已具备 RGB、LiDAR range、法向/表面锚定、透明度/尺度等损失入口。
- 已实现 classic gradient split/clone/cull 适配路径；snow 竞品运行的 MCMC relocation 明确关闭，不能用旧的 error-weighted MCMC 冒充竞品路线。
- 竞品恢复出的参考参数、loss 调度和 densification 阈值保存在静态审计中；当前 LiDAR 原生路线只选取有第一性原理价值的部分，不追求逐字节复刻。
- `mipmap_gate.py` 把“上游数据就绪”和“训练实现对位/受限 smoke”分开，避免 `TRAINING_READY` 名称误导。
- 相关入口：

### 3.7 天空、导出和质量审计

- 支持独立 100k 天空层、surface/sky/combined 分层 PLY 导出和签名边界校验。
- v22j 候选已经生成完整/表面/天空 PLY 和质量报告；生成物不进 Git，但路线和复现配置已提交。
- 最终候选的历史记录指标为：36 帧 PSNR 17.4144 dB、P10 15.5631 dB、SSIM 0.52808、LPIPS 0.57027；仍不能据此声称全面超过竞品。

## 4. 最新测试与明确未完成项

冻结同步前的直接证据：

- Tile 几何与 FaceDataset 定向测试：20/20 通过；
- MipMap Gate 定向测试：15/15 通过；
- 五 Tile 组件 GPU smoke：全部通过；
- 之前的 AT、采样身份重绑定、天空分层导出定向回归：18/18 通过；
- 2026-08-28 同步前完整回归共运行 624 项：619 通过，2 项因外部真实 LiDAR 不在本机而跳过，3 项因本机 `gsplat` CUDA 扩展与当前源码不匹配而报错。三个报错分别是扩展未编译单通道颜色支持，以及缺少 `projection_ewa_3dgs_fused_fwd` 算子；它们属于运行时构建阻塞，不能记作 PASS，也不是本轮 LiDAR/Tile 合同的新失败；
- 新增的 preset/AB matrix 回归 8/8 通过，`implementation_smoke_only` 合同测试已包含在上述完整回归中并通过。

仍未完成：

1. Tile_1 的真实 2-step raster smoke。第一次运行在训练循环之前被 20-epoch 采样合同拦截，实际训练步数为 0；修正后的受限 smoke 配置尚未重新运行。
2. 本机 `gsplat` CUDA 扩展需要按锁定源码重新构建，补齐单通道颜色和 EWA 投影算子后，才能把完整回归升级为全绿。
3. 尚未开始 LiDAR 原生五 Tile 正式长训练。
4. 澳洲机器尚未完成 CUDA/gsplat、真实数据盘和外部 PLY Viewer 的独立验收。

因此当前状态是：`UPSTREAM_DATA_READY + COMPONENT_SMOKE_PASS`，不是正式训练 GO，也不是产品质量 GO。

## 6. 澳洲机器建议接手顺序

### 6.1 代码和基础测试

```powershell
git clone https://github.com/yang498-Peter/cloudstudio-3dgs.git
Set-Location cloudstudio-3dgs
git switch master
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

训练环境另外参考：

- `train/setup_new_machine.cmd`
- `train/run_smoke_gs2.cmd`
- `train/patches/README.md`
- `upstream/gsplat.lock.json`

不要在 CUDA/torch/gsplat 锁未验签时直接启动正式训练。

### 6.2 需要另行复制的数据

Git 不包含以下内容：

- 原始 snow 双鱼眼照片、POS、LAS；
- `outputs/snow-20260224-full-20260825/` 下的签名数据阶段；
- Face4 RGB/Mask、稀疏 LiDAR range、Tile 深度 NPZ；
- 初始化 PLY、checkpoint、最终 PLY、HTML 质量报告；
- MipMap 客户任务目录和完整动态证据副本。

复制后必须先比较 Manifest SHA 和文件摘要，不能只比较目录名。

### 6.3 下一轮最小可执行门槛

1. 按 `upstream/gsplat.lock.json` 重新构建 CUDA 扩展，完整回归不再出现当前 3 个运行时算子错误；
2. CUDA/gsplat 最小 smoke 通过；
3. 数据 Manifest、五 Tile bundle SHA 和训练配置验签通过；
4. 重新运行 Tile_1 的受限 2-step raster smoke；
5. 记录真实峰值显存、range loss 是否反传、0/2 步 checkpoint 与 Run Manifest；
6. 只有 smoke 通过后，才决定是否启动单 Tile 短训练；五 Tile 长训练仍需单独 GO。

## 7. Git 与证据边界

- 本次提交只包含小型源码、测试、配置索引、SOP、研究文档和缺陷报告。
- `outputs/`、大型 `results/`、`.tools/`、临时编译文件、NPZ/PLY/checkpoint 不进入 Git。
- 研究文档中的“直接证据、抽样测量、静态能力和推断”必须继续分开；DLL 存在某个符号不能自动证明 snow 运行启用了该路径。
- 推送完成后，应分别验证当前工作分支和 `origin/master` 的 SHA；不能把“本地 commit 成功”当作 GitHub 已同步。
