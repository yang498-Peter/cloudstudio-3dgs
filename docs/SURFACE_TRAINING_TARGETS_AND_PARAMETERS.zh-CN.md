# 表面高斯训练：质量目标与参数基线

更新日期：2026-08-30
适用：house0305 全分辨率 Face4 路线，以及后续同类场景

本文只记录**我方的质量目标与训练参数选择**，以及每项选择的工程理由。数值目标以我们要达到的交付质量水平表述，不涉及来源讨论。

## 1. 形态与容量目标

我们当前交付件（D1）与目标水平的差距是可测量的，且是**四个乘性因素叠加**：

| 指标 | 目标水平 | D1 实测 | 差距 |
|---|---:|---:|---|
| 高斯总数 | 约 2245 万 | 7,453,193 | 3.01× |
| 最长轴 P50 | 4.4 mm | 12.818 mm | 粗 2.91× |
| 最短轴 P50 | **0.43 mm** | 5.006 mm | **厚 11.70×** |
| 轴比 P50 | **10.2** | 2.297 | 扁平度差 4.46× |
| opacity P50 | 0.20 | 0.5724 | — |
| opacity < 0.1 占比 | 21% | 33.84% | 我方死质量更多 |
| 场景包围盒 | 紧致（约 113×118×34 m） | 761.7×665.6×638.7 m | 我方有大量离群漂浮 |

第四个因素是我方自设的：`experiments/runs.csv` 中 house0305 的 41 条训练记录全部是 `f2_fisheye`，D1 与 W3 的 `run_manifest.json` 直接写着 `"factor": 2`。**我方从未在全分辨率上训练过这个场景**，这单独就是 2× 的线性细节损失，且与上述三项相乘。

用户长期反馈的"细节看不清、不锐利、高斯没有按细节自适应变小"，由这四项共同解释。

## 2. 训练参数基线

```
factor                  = 1            # 底线，不得以提速为由退回 2
RGB 损失                = 0.8·L1 + 0.2·(1−SSIM)
致密化起始 / 间隔        = 500 / 100
opacity reset           = 每 30 个 refine 周期（即每 3000 步），上限 0.2
致密化 2D 梯度阈值       = 2e-4 起步，必须按本场景梯度分位重新定标
clone/split 尺度阈值     = 0.01（percent-dense 约定，× 场景尺度）
split 子点尺度           = 父点 / 1.6，子点数 2
cull 阈值               = opacity 0.05 / world 0.2 m / screen 0.1
学习率                  = means 1.6e-4 → 1.6e-6（log 空间指数插值）
                          scale 5e-3, quat 1e-3, SH-DC 2.5e-3,
                          SH-rest 1.25e-4, opacity 5e-2
```

**梯度阈值必须现场定标**，不能照抄。V42a 实测本场景梯度分布 P50/P95/P99 = 2.11e-5 / 7.71e-5 / 1.50e-4，若直接用 2e-4 只会选中约最高 1% 的父点，致密化几乎不发生。雪堆场景据此定标为 7.5e-5。

## 3. 单步循环顺序

```
更新 means LR → 清梯度 → forward → （可选光度校正）→ RGB 损失
  → 可选几何损失 → backward
  → 拓扑生命周期（clone/split/cull）      ← 在 Adam 之前
  → Adam step
  → 超尺寸收缩                            ← 每步必做，在 Adam 之后
  → 可选相机位姿精修
```

两处顺序需要对齐而我方当前不一致：

1. **生命周期在 Adam 之前**（我方 V37 复盘已发现）
2. **Split 先于 Clone**（我方 `default_strategy_adapter.py` 中 `duplicate()` 在 501 行、`split()` 在 649 行）。两个掩膜互斥（`small` vs `~small`），实际只影响索引布局与优化器状态排布，优先级低。

## 4. 已实现的两项形状机制（2026-08-30）

### 4.1 保形的超尺寸收缩 `world_shrink_factor`

原实现是逐轴硬 clamp：

```python
params["scales"].clamp_(max=log(max_world_size_m))
```

对 `(1.0, 0.5, 0.001)` m 的高斯会得到 `(0.2, 0.2, 0.001)` —— 两个相差 2 倍的长轴被压到完全相等。**这个本用于消除巨型高斯的保险，实际上在它触及的每个高斯上抹平各向异性，与我们用形状正则追求薄片的目标直接对抗。**

新实现保留同一触发条件，但对超限高斯的**三轴同乘一个常数**：`(1.0, 0.5, 0.001) → (0.8, 0.4, 0.0008)`，约 `ceil(log(0.2)/log(0.8))` 步后落入阈值内，2:1 比例完整保留。硬 clamp 仍为默认，新行为按配置开启。

推荐配置：`max_world_size_m = 0.2`，`world_shrink_factor = 0.8`。

与 cull 的世界尺度删除阈值（同为 0.2 m）构成双层巨型高斯防护：收缩是渐进的第一道，删除是兜底的第二道。

### 4.2 切向各向同性 `weight_tangent_isotropy`

压最短轴只约束一个轴，对另外两个轴不置一词。**针状（s2 ≫ s1 ≈ s0）与圆盘（s2 ≈ s1 ≫ s0）在原有损失下得分相同**，但只有圆盘能有效覆盖表面。

新项在同一 planarity 加权锚点集上惩罚 `(s_max/s_mid − 1)²`，尺度无关，对任意大小的圆盘均为零。默认权重 0。

这解释了我方 V48b"方向对但幅度远远不够"的原因：只压厚度不能决定剩下两轴的关系。

## 5. 达成薄圆盘形态的完整损失组合

| 项 | 作用 | 我方状态 |
|---|---|---|
| 最短轴惩罚 | 变薄 | 已有（`weight_flatten`） |
| **切向各向同性** | 圆盘而非针状 | **本次新增** |
| 整体尺寸惩罚 | 控膨胀 | 可选，默认 0 |
| LiDAR 覆盖地板 | 防止靠降 opacity 作弊 | 已有（`lidar_alpha_target`） |
| 法线对齐 | 短轴贴合表面法向 | 已有（`weight_align`） |

前两项**必须同开**才能得到薄圆盘；只开第一项会退化成不可预测的薄形。

## 6. cull 安全阀（语义已定，尚未实施）

当某一轮 refine **没有产生任何 clone 或 split** 时，放宽三个 cull 阈值：opacity 门 ×0.25（更难删）、world 与 screen 门各 ×5（更难删）。

即"没补新点就少删点"，防止人口在无补充的情况下持续净减。这是**防崩塌机制**。

我方 V33a/V40 系列反复出现的"裁剪要么崩塌要么无效"，此机制的缺失是候选解释之一，但尚未验证。实施前需要在真实训练中单独 A/B，不与形状改动同轮开启。

另有一处独立观察：opacity 阈值在训练前半段额外 ×2（早期裁剪更激进）。

## 7. 独立天空

天空作为**独立模型**训练与导出，不并入表面 PLY。我方 V31 已用失败结果证实：把照片球壳合入主体会造成背景颜色穿透墙面。

目标规格：100,000 点、SH0、包围盒约 404×404×284 m（半径约 202 m）、最长轴 P50 约 2.06 m、轴比 P50 约 1.52（近各向同性）、opacity P50 约 0.10。

### 7.1 天空必须在训练期就在场（2026-08-30 止损决策）

stage C 跑到 12k 步时的三方对照图暴露了结构性问题：**没有天空层的训练里，
天空像素只能由表面高斯买单**。两个后果，且都不会随训练自愈：

1. 树顶、屋檐附近的表面高斯被 RGB 梯度拽离表面去"画云"，渲染出天空絮状伪影，
   同时这部分容量从地面和建筑上被挪走；
2. 白背景能透出来的地方，颜色损失允许高斯降不透明度来混色——stage B 结束时
   opacity P50 掉到 0.0637（参考 0.1974）、56.8% 低于 0.1，正是这个机制的读数。

处置：杀掉 stage C（认掉 12k 步），把照片烘焙球壳（`build_sky_dome.py` 产物，
100k 点、半径 P50 约 250 m、颜色由照片鲁棒中位数烘焙）经
`augment_checkpoint_sky.py --prebaked` 拼接进 12k 检查点，以 warm start 重启为
stage C v2（剩余 51,460 步，总步数不变）。训练期天空像素由球壳解释，表面高斯
从两条歪路上同时解放。烘焙壳与程序壳的区别：程序壳是均色起点、全靠联训学色；
烘焙壳开局就是照片颜色，抢占预算少——上一轮联训天空实验（w3）的边角回退
教训由此规避。

导出时按行号切开（`sky_layer.sky_gaussian_start` 起是壳），主体与天空仍是
两个 PLY，遵守本节与 §8 的纪律。

一个必须知道的陷阱：`warm_start_min_opacity` 是**裁剪**（删除低于阈值的行），
不是抬底。在 56.8% 低于 0.1 的状态下用它等于删掉大半个模型。不透明度的恢复
只能靠移除压力源后让训练自己走回来，盯 `shape_opacity_p50` 曲线。

## 8. 导出纪律

- 主体 PLY **不做 opacity 裁剪**。V30 按 `opacity < 0.005` 删除 801,522 点，直接造成墙体、雪面与远景被背景穿透。
- 导出前按场景 ROI 裁剪离群漂浮（我方包围盒比目标水平大一个量级）。
- 尺度上限只加在主体，不缩小天空壳。

## 8.5 密集 LiDAR 初始化：容量目标的直路（2026-08-30）

完整 `colorized.las` 是 **18,757,869 点**。此前所有容量推算都误用了 `6,252,623` —— 那是深度缓存按 `--max-points 8000000` 抽稀后的数，不是点云本身。基数错了三倍。

这件事对画质是有利的意外：

| | 点数 | 距 2245 万目标 |
|---|---:|---|
| 完整 LiDAR 初始化 | **18,757,869** | **84%，几乎不用生长** |
| 我方历史初始化（`init_2m`） | 1,860,000 | 需生长 12× |
| 我方历史交付（V50c 合并） | 7,036,339 | 需生长 3.2× |

**生长正是我方反复失败的环节**：V33a 在 step 700 一次删 36 万导致崩塌；V40–V46 系列在 step 600 后覆盖持续退化，关闭 opacity cull 也没救回来；G 线的无守卫出生堆出 250 万漂浮。历史上每次都要靠生长翻 3–12 倍才够密度，每次都在这里栽。

密集初始化把数量直接送到位，等于**把"能不能长起来"这个高风险问题，换成"能不能把已有的点修好"这个低风险问题**——而后者我方已有验证过的配方（V48b/V50c：先修覆盖、再改形状、中心冻结）。

显存核算（本机 12.92 GiB 预算，实测拟合 `0.57 + 0.332×百万`）：

| 场景 | 峰值 | 结论 |
|---|---:|---|
| 1876 万，**冻结拓扑** | **6.80 GiB** | 宽裕 |
| 1876 万，生命周期 ×1.5 | 9.91 GiB | 可行 |
| 1876 万，生命周期 ×3.0 | 19.26 GiB | 超预算 |

冻结拓扑下单块即可承载，无需切分，halo 重叠 1.00×。

**注意**：深度缓存仍是 625 万点的抽稀版本。它只用于像素级深度监督（逐图 Z-buffer），与初始化点数无关，两者不必一致；但记录时不要混用这两个数字。

## 9. 单目深度：本路线不做（2026-08-30 决策）

**决策：单目深度从本路线移除。** 除非后续出现明确、可证伪的需要，否则不再计算。

### 9.1 它为什么曾经在链条里

我方的几何真值权威是 LiDAR，单目深度的**训练损失权重是 0**，一个梯度都不贡献。它此前存在的唯一原因是一条依赖链：

```
Tile 计划  需要  天空门  需要  单目深度
```

而天空门在分块器里**只是身份绑定的载体**——它携带各上游清单的 SHA256。真正的分块几何来自 LiDAR 可见性观测与点云包围盒，**不消费任何天空或单目深度数据**。

这是一条**伪依赖**：表面训练的分块规划，被挂在了一个它根本不读取的信号上。

### 9.2 成本核算

house0305 实测：3544 个面，约 27 面/分钟，合计约 2 小时 GPU，标定成功率仅 **57%**（train）/ **32%**（val）。

成本被两处放大：

1. **逐面推理而非逐图**。单目深度本质是逐图像的预处理；四个面是同一张原图的不同裁切，深度信息完全冗余。886 张原图跑成 3544 个面 = **4× 纯浪费**。
2. **米制标定昂贵且易失败**。RANSAC 单一全局仿射拟合室内外贯通场景的深度跨度，过不了 5% 内点门是必然的。而**天空判别本质上只需要"比所有有 LiDAR 回波的地方远得多"这个相对判断，不需要米制**。

### 9.3 若将来确有需要

先证明需要，再谈实现。真要做时按以下形态：

- **在原始鱼眼上估计，不在派生面上**（省 4×）
- 用于天空判别时**不做米制标定**（省掉那个 57% 成功率的 RANSAC），用相对深度 + 无 LiDAR 回波 + 世界方向即可
- 只有当它要作为**带非零权重的深度监督**进入损失时，才需要米制对齐

### 9.4 天空的替代判据

天空判别不依赖单目深度也能成立，可用的三个信号我方全部已有：

- **无 LiDAR 回波**：深度缓存直接给出（886/886 完整）
- **世界方向朝上**：相机位姿直接可算
- **相对远**：可由几何或简单先验给出

需要单目深度消歧的只有一种情况：某像素无 LiDAR 回波，究竟是天空，还是 LiDAR 漏掉的表面（玻璃、深色材质、超出量程、对扫描仪遮挡）。这种消歧**可以延后**，且不应阻塞表面训练。

## 10. 待定项

- **梯度阈值的本场景定标值**：需在真实训练中扫描梯度分位后确定
- **RGB 权重 0.8/0.2 与我方 SOP 现行 0.6/0.4**：两者需 A/B 定夺，不得假定其一必然更优
- **cull 安全阀**：语义清楚，等形状改动的效果可归因后再单独验证
- **逐相机光度模型**：当前 PPISP 是受控光度补偿；更完整的方案是逐相机 `exp(g)·I + b`（独立优化器，lr 1e-3），或空间变化的网格式校正（`[N,12,8,16,16]`，带 TV 正则与独立 Adam，lr 2e-3）。影响跨相机色彩一致性，不直接影响锐度，优先级低于 §4–5。
