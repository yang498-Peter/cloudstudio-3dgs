## 2. 同一张照片在两个 Tile 学到的 gain 不一致（跨 Tile 一致性）

884 张训练父图中 846 张被 ≥ 2 个 Tile 训练（halo 重叠）。同一张图各 Tile 学到的 log gain 极差：

| 分组 | n（图） | 中位 | 均值 | P95 | 最大 |
|---|---|---|---|---|---|
| 全部 | 846 | **0.177** | 0.215 | 0.505 | 1.029 |
| 全部，扣除各 Tile 烘焙中位后 | 846 | 0.170 | 0.212 | 0.499 | 1.010 |
| indoor | 282 | **0.289** | 0.307 | 0.625 | 1.029 |
| outdoor | 422 | 0.150 | 0.159 | 0.324 | 0.534 |
| covered | 98 | 0.172 | 0.230 | 0.560 | 0.729 |

两两 Tile 对（|Δ log g|，中位 / P95）：T0~T1 0.104 / 0.333，T0~T2 0.123 / 0.456，T0~T3 0.091 / 0.322，T1~T2 0.089 / 0.319，T1~T3 0.105 / 0.413，T2~T3 0.118 / 0.508。

读法：
* 单个 Tile 内 log gain 的 σ 是 0.18–0.22；同一张照片两个 Tile 的差中位 0.09–0.12、P95 0.32–0.51。即**每图 gain 的变化量里约一半在换一个 Tile 后不可复现**——它不是这张照片的曝光属性，而是"这张照片对这块模型的亮度残差"，取决于该 Tile 看到了照片的哪一部分场景、模型自己的亮度。
* 合并只减去每 Tile 一个标量，跨 Tile 差在扣除后几乎不变（0.177 → 0.170）；室内 P95 0.63（约 1.9×）。合并后同一表面在接缝两侧的 DC 亮度被不同的每图残差"拟合"过，这是任务书 §1.2 D 指出的"不同 Tile 各自训练同一照片的曝光"问题的实测量级。
* 这直接反对"每图 gain = 相机曝光值"的解释；支持任务书 §9 "同一张图在多个 Tile 中的补偿需要全局一致或固定共享先验"。

* 四块的中位 gain 都 < 1（0.88–0.93）：**单块 canonical 渲染比训练照片亮 7–13 %**（Tile_0 最重，13 %）；评估器与训练器验证都在这个帧里打分（`01_exposure_policy_audit §2, §4`）。不是"标准外观偏暗"，而是偏亮。
* 合并烘焙把每块中位拉回照片帧，但每图残差不变：室内 P5–P95 −0.38..+0.54（0.68×–1.72×），室外 −0.14..+0.28。即交付模型对任何一张具体室内照片的亮度，仍有 ±40–70 % 的"被 gain 吸收掉"的差异；这些差异到底是照片曝光、还是模型对该视角的亮度错误，§4 用多视图颜色离散度区分。
* 已有对照：`02_schedule_audit` E001 已警告无 zero-mean/anchor；P8 probe 记录硬 zero-mean 表现不佳（`exposure.py:118-124` 注释）。本文数字说明"全局漂移"量级是每块 7–13 %、每图 ±20 %（σ），软锚只需处理前者。

## 4. 同一物理表面跨视图的颜色离散度：gain 前后（WP03 区域）

方法：`03_roi_provisional.json` 两个框各随机 600 个 LiDAR 点（seed 20260911，Tile 初始化 PLY），投影到 884 张训练父图的原始鱼眼；"有效视角"沿用 WP03 strict 规则（面 mask 有效、vis6 在 13×13 px 内有 0.1 m + 3 % 带内返回且无更近返回）；颜色 = 原图投影处 5×5 中值（sRGB 8-bit，与训练同域）；亮度 = ITU-R 601。每点 ≥ 3 个有效视角才计入。"gain 后" = `photo / g_i`，g 取**训练该区域所属 Tile 的检查点**（Tile_1 对门扇，Tile_0 对砾石）；该 Tile 未训练的视角被丢弃，并把 raw 基线配对到同一视角集合（`*_raw_paired`）。变体：

* `learned`：训练学到的每图 gain；
* `per_camera_mean`：每台相机一个常数（该 Tile 学到 gain 的相机几何均值）；
* `per_camera_time_block_{10,20,60}s`：每相机每时间块一个常数（块内学到 gain 的均值）；
* `oracle_per_image`：直接由这些多视图观测交替中值拟合的每图标量（几何均值归一），是"任何每图标量能达到的下限"，**不是**可部署的方法。

读法：
* **室内**：每图 gain 确实在做工作——CV 0.516 → 0.435（−16 %），98 % 的点改善；但 oracle 说明一个每图标量本可以做到 0.240（−54 %）。学到的 gain 与 oracle 方向一致（相关 0.55）而幅度只有 16 %（斜率 0.16，σ 0.17 vs 0.60）：gain 被 L2 先验（1e-2）和"对模型渲染而非对多视图一致性拟合"压小，其余亮度矛盾由模型自身吸收（这正是任务书 §1.1 说的"平均成洗白纹理"）。
* **室外**：每图 gain 几乎不做工作（−1.2 %，39 % 的点反而变差），但**把同一批 gain 按每相机 20 s 块取均值后反而 −11 %，99.7 % 的点改善**。即室外 gain 的逐帧高频部分与真实多视图一致性无关甚至相反（在拟合模型残差 / 操作员影子），平滑分量才是曝光。
* **每相机常数**在两区都无效（比值 1.00），与 §5 的 camera R² < 0.02 一致；60 s 块室内无效、室外有效——室内的曝光漂移时间尺度更短（穿门、窗外强光）。
* oracle 的 −50 % 是上限而非目标：它也吸收了门扇移动、背面视角、操作员影子和 BRDF；RGB 逐通道 σ 在 oracle 下仍有 17–22 灰阶，标量 gain 之外还有色彩/局部成分。
* 提醒：本节 raw CV（室内 0.52、室外 0.25）比 WP03 的 0.44 / 0.23 高，是因为这里用 5×5 中值的点亮度而 WP03 用 64 px 窗均值；两者都只作同区域内的相对比较。

## 5. 低维共享校正的证据（每 Tile log gain 的方差分解，adjusted R²）

|---|---|---|---|---|---|---|---|---|---|---|
| Tile_0 | 0.004 | 0.121 | 0.059 | 0.227 | **0.489** | 0.361 | 0.064 | −0.06 | 0.205 | 0.82 / 0.84 |
| Tile_1 | 0.003 | 0.002 | −0.41 | 0.091 | **0.525** | 0.412 | 0.080 | −0.14 | 0.291 | 0.85 / 0.89 |
| Tile_2 | 0.017 | 0.050 | 0.075 | 0.195 | **0.497** | 0.325 | 0.110 | +0.12 | 0.139 | 0.84 / 0.80 |
| Tile_3 | 0.009 | 0.094 | 0.008 | 0.196 | **0.425** | 0.375 | 0.104 | +0.00 | 0.167 | 0.82 / 0.83 |

（未调整的 rig frame R² 0.51–0.72 是 ~440 个组、每组 1.6 张造成的虚高，调整后 ≤ 0.08；表中已用 adjusted 值。）

* **相机常数解释不了 gain**（R² < 0.02）；左右相机在同一 rig 帧上的 gain 相关 ≈ 0，绝对差中位 0.14–0.29（15–34 %）。两台相机的自动曝光互不相关——与 `exposure.py` 注释"按物理相机分组锚定"的前提一致，但说明**一个共享的每帧（rig）校正不成立**。
* **每相机的时间序列是平滑的**：0.5 s 相邻帧 lag-1 自相关 0.80–0.89；camera×10 s 块能解释 43–53 % 的方差，camera×60 s 只有 6–11 %。也就是 gain 里可共享的结构是"每相机、约 10 s 尺度的漂移"，不是全局或每分钟常数。
* 剩余 ~50 % 的方差是块内逐帧的；§2 已表明其中约一半又不能跨 Tile 复现。因此可稳定估计、值得共享的自由度约是 2 相机 × ~23 个 10 s 块 ≈ 46 个参数，而不是 884 个。
* environment 只解释 ≤ 12 %；室内的额外离散不是一个常数偏移，而是逐帧的（§1）。

## 6. 结论：每图标量 gain 在做什么工作

| 问题 | 判定 | 依据 |
|---|---|---|
| 每图标量 gain 是否减少同一表面的多视图亮度矛盾 | **室内：是，但只做了可做工作的约 1/3**（CV −16 %，oracle −54 %）；**室外：否**（−1 %），其平滑分量才有效（−11 %） | §4 |
| gain 是不是这张照片的曝光属性 | **大部分不是**：同一张图两个 Tile 学到的值中位差 18 %（室内 29 %），扣除 Tile 中位后不变；与 oracle 的相关只有 0.28–0.55、幅度 0.16–0.19 | §2, §4 |
| gain 的可共享结构 | 每相机、约 10–20 s 尺度的平滑漂移（camera×10 s 块 adj R² 0.43–0.53；lag-1 0.80–0.89）；两台相机互不相关（同帧相关 ≈ 0）；相机常数、环境常数、60 s 块都解释不了 | §5 |
| 标准（canonical）外观 | 单块 canonical 渲染比照片**亮** 7–13 %（Tile_0 最重）；合并烘焙拉平中位后，每图残差室内 ±40–70 %、室外 ±15–30 % 仍在，并且这些残差不能跨 Tile 复现 | §2, §3 |
| 饱和 | 高光饱和（≥ 250）平均 1–2 %，与 gain 无关（相关 0.01） | §1 |
| 室内 vs 室外 | 室内 gain 离散 1.9×、clamp 触顶 3.4 % vs 0.3 %、跨 Tile 差 1.9×、raw 亮度 CV 2×；室内是光度矛盾的主战场，但每图 gain 在室内也只做了 1/3 的工作 | §1, §2, §4 |

因此：证据支持任务书 §9 的"低自由度优先"——一个**每相机、按时间平滑、带软锚、全场共享**的校正（X1）预期保住室内每图 gain 约 2/3 的收益（10 s 块 −11 % vs −16 %），在室外反而更好（−11 % vs −1 %），并从构造上消除跨 Tile 不一致和每块不同的 canonical 亮度。它**不会**把室内的亮度矛盾降到 oracle 水平；剩下的 ~40 % 是否值得用更高维（每相机 RGB、渐晕、PPISP）去吸收，要先看 X1 之后 canonical 渲染的锐度是否随之改善，而不是只看 CV。

## 7. 零均值 / 锚定的需要

* 需要锚定的是**每 Tile 一个全局亮度自由度**：四块中位 gain 0.88–0.93 使 canonical 帧比照片亮 7–13 %，且四块不同（Tile_0 与 Tile_3 差 5.8 %），合并靠事后 DC 烘焙补。软 mean-anchor（`mean_anchor_weight > 0`，按相机分组）直接作用于这一项，不限制逐帧差异。
* 不应做的是硬 zero-mean 投影：P8 probe 已记录其破坏结构监督（`exposure.py:118-124`）；本文 §5 也表明逐帧差异是真实的每相机时间漂移，硬投影只是把均值搬走，不减少逐帧自由度。
* 跨 Tile 一致性（§2）不是锚定能解决的：两个 Tile 对同一张图学到不同 gain，扣掉各自中位后差不变。需要的是**共享的 gain 参数**（先全场估计、再冻结给各 Tile），这是任务书 §9 的"先全场求稳定校正，再冻结训练分块"。

## 8. X0 / X1 臂定义（低自由度优先）

固定：pose、几何监督、初始化、增殖、cap、步数、评估协议（`01_eval_protocol.json`）全部与 R1d 相同；只改光度校正的参数化。两臂都在同一 Tile（先 Tile_1 室内，再 Tile_0 室外对照）上跑，并同时报告 canonical 与 train-compensated 渲染。

* **X0（对照，现状）**：每父图一个标量 log gain，L2 1e-2，无锚定，每 Tile 独立学习。= R1d。
* **X1（共享低维校正）**：每物理相机一条按捕获时间参数化的平滑 log-gain 曲线（分段常数或线性样条，节点间隔 10 s，≈ 2 × 23 个参数），带软均值锚（每相机曲线均值 → 0，SmoothL1）；**先全场估计一次，四个 Tile 冻结复用同一条曲线**。每图残差自由度取消。判据：
  1. §4 的同一表面跨视图亮度 CV（gain 后）不劣于 X0 的 `learned` 变体；
  2. canonical 渲染的训练视角与离轨迹锐度、以及 `02` 的保留集 P10；
  3. 合并后同一张图跨 Tile 的 log gain 差恒为 0（构造保证），接缝两侧 DC 亮度差；
  4. 室内、室外分别报，不取平均。
* 只有 X1 不劣于 X0 且室内光度矛盾（§4 raw CV）仍显著高于 X1 后残差时，才进入下一级（每相机 RGB 3 维白平衡，同样共享+锚定）；PPISP/bilateral grid 排最后。

## 9. 无法核实 / 残留

* 未做任何渲染：§3 的 canonical/compensated 差是由 gain 推出的恒等式，不含 SH 高阶带、背景合成或 alpha 影响；`01_exposure_policy_audit §3` 已指出合并只烘焙 DC 带。
* §4 的"有效视角"只用 strict LiDAR 支持，门扇 4 cm 厚度使背面视角混入（WP03 §2 已述）；门扇可动、砾石有操作员影子，二者的 raw 离散里含真实场景变化，任何标量都不应把它压到 0。
* 每图 gain 是 20k 步终态；未看训练过程中 gain 的演化，也未区分 gain 的高频部分是曝光还是模型残差——§4 的 `oracle` 与 `learned` 相关度是唯一的间接证据。
* ROI 仍是临时框；`01_roi_registry.json` 落地后应重跑 §4。
