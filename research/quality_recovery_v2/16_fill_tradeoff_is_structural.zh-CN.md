# 16. 填充层的取舍是结构性的，以及真正的根治方向

日期：2026-09-15。本文把两条筛选轴的失败合并成一个机制解释，并写下我认为的根治方向——**它还没有被实验验证**，写在这里是为了让下一轮有一个可证伪的目标，不是结论。

## 1. 已测过的两条筛选轴，都失败

交付件的覆盖缺口来自归属遮罩：切片被告知"这些像素不归你画"，训练时由替身背景顶上，但替身不进交付件。填充层从一个全场先验里挑行补进去。问题是补进去的行在**新视角**里挡住细结构。

| 轴 | 规则 | 结果 |
| --- | --- | --- |
| 尺寸 | 长轴 ≤ 50 mm / ≤ 20 mm | 锐度回到不填充水平（0.447 vs 0.444），**覆盖也回到不填充水平**（0.190 vs 0.189） |
| 到 LiDAR 表面的距离 | ≤ 2.0 m | 只丢 1.4% 的行，与不加规则不可区分 |
| | ≤ 0.5 m | 丢 17.6% 的行，**覆盖掉 57%，锐度只涨 8%** |

两条轴互相正交，结论一致：**掉覆盖永远远快于换锐度**。

**最干净的一条证据**：`axis20c0`（体素 0.2 / clearance 0 / 长轴 ≤ 20 mm）保留了 **81.3 万行**，比 `sharpc1` 的 **65.8 万行还多**，覆盖却只有 **alpha p05 0.191**，而 sharpc1 是 **0.722**。**行数不决定覆盖，行的大小才决定。**把 >20 mm 的行删掉之后，剩下多少小行都补不回覆盖。

## 2. 机制：覆盖与遮挡是同一批高斯的同一个属性

一个"缺口"是一段**没有任何交付高斯占据的体积**。能在图像上把这段体积盖住的，只能是投影面积足够大的高斯——也就是长轴大的那一批。而"投影面积大"在新视角里就等于"挡住的东西多"。

所以它不是两个可以分开的群体，而是**同一个量的两面**：

- 在训练视角里，填充行背后**本来就看不见**（那正是它被判为"缺口"的原因），所以它只贡献覆盖，不造成可见的遮挡；
- 换到新视角，同一个行的背后出现了真实结构，于是它从"补洞"变成"挡路"。

这解释了为什么按**行的属性**（尺寸、位置、opacity）筛选注定失败：冲突不在行里，在**视角**里。任何只看行的规则，都不可能区分"这一行在哪些视角下是对的"。

诊断数据支持这个解释：锐先验整体长轴 p50 7.6 mm，但**被占据规则留下的那批**是 21.7 mm、p90 145 mm——占据规则本身就在结构性地挑大的，因为只有大的才落在"没人占据"的体素里。

## 3. 那么覆盖缺口的根治在哪里

**缺口不是"没人拥有"的体积，是"有人拥有但那个人没看见"的体积。**两条既有测量支持这个判断：

1. 四个 core box 是全场无缝划分，每个 `training_and_export_box` 都包含自己的 core —— 所以任何一段体积**在名义上都有主**（`2c28465` 的实测：先验 240 万行 100% 落在某个盒内）。
2. 填充行只有 **1.6%** 在交付件自身包围盒之外（`18cac90`）——缺口几乎全在"名义有主、实际没画"的体积里。

那为什么owner没画？因为**owner 的视角集里没有能看见那段体积的图**。归属遮罩把像素从"非 owner"的监督里排除是对的，但如果 owner 自己也没有这张图，这段内容就没有任何切片负责。

**可证伪的预测**：把每个切片的视角集从"按相机位置/投影面积选出的视角"扩展为"**能看见本切片所拥有内容的全部视角**"，覆盖缺口应当在训练阶段就消失，交付件不再需要填充层，因而也不用付新视角锐度的代价。

**检验方式（便宜的先做）**：不必先重训。取当前四个切片的归属遮罩缓存，统计**每一个被判为 foreign 的像素**，它所属的 owner 切片的视角集里是否包含这张图。如果"owner 没有这张图"的比例很高，预测成立；如果 owner 大多有这张图（只是没画好），那预测就错了，缺口另有原因。这一步只读缓存，CPU 几分钟。

**如果预测成立**，代价是切片视角集变大 → 训练步数（20 epoch × 视角数）与显存上升，需要重新定 cap，属于一轮完整的四切片重训（约 8 h GPU，预取打开后约 5 h）。

### 3.1 这条预测已被实测推翻（2026-09-15 05:48）

按上面的办法查了：**98.2% 的"有像素被丢弃"的样本，确实有别的切片持有同一张图**；被丢弃的像素里只有 **0.1%** 落在"没有任何别的切片持有这张图"的样本中。**owner 绝大多数时候是有那张图的。**扩大视角集补不上这个缺口，预测错误，作废。

### 3.2 换一个候选：没有 LiDAR 证据的像素被所有切片同时排除

归属是靠 **LiDAR 投影**判的：某切片的 LiDAR 投到这个像素 → owned；别的切片的 LiDAR 投到这里 → foreign。**两者都没有的像素既不 owned 也不 foreign**，于是落进每一个切片的膨胀 foreign 带里，被所有切片一起排除。

实测支持：**整张面里只有 6.8% 的像素有任何 LiDAR 证据**（深度遮罩 8.03 亿 / 裁剪 118.06 亿），93.2% 没有；按计数上界算，**47.8% 的被丢弃像素是任何切片都无法"正面拥有"的**；而丢弃最多的前五个样本**全是 `pitch_up_56`**（朝上看的面），每个丢约 300 万像素而全部切片加起来只拥有约 20 万。

### 3.3 但更重要的是：门禁一直在给半个产品打分

`pitch_up` 是天空所在的方向。顺着这条线查到了一个**测量缺陷**：

- 交付件是 **body PLY + 一张冻结的 sky PLY**，`tools/pipeline.py` 的 `publish_run` 只是把两个文件**并排拷到一起**；
- **没有任何评估器把它们合成**，battery 评的是 `reimported.pt`，也就是**只有 body**；
- body 的天空区域**本来就该是透明的**（天空交给 sky 层），而 `alpha_p05` 把这份正确的透明**计为覆盖失败**。

于是填充层可以靠**把天空画进 body**来抬 alpha 与 PSNR ——这正是用户目视报告的"屋檐上长出凸起高斯去拟合蓝天"。逐面证据吻合：从填充最少到填充最多的变体，**朝上的面 +2.241 dB，朝下的面只有 +0.312 dB**（7 倍差距）。

**待测（已排队 `day_plan24.cmd`）**：把 sky 层拼回 body，在同样 48 个视角上重测。**如果不填充的 body + sky 已经过 alpha 门槛，那么整条填充层路线回答的是一个测量缺陷，而不是真实的覆盖缺口。**在这个结果出来之前，本文第 4 节的交付建议都应当视为暂定。

## 4. 在根治之前，怎么交付

取舍曲线是真实的，所以**只能按用途选工作点**，并在交付报告里把两个数都写出来：

- **要覆盖**（正射、俯视、贴近采集轨迹的浏览）：sharpc0，alpha p05 0.825、battery PSNR 19.311，两项都超过历次交付；锐度 0.354。
- **要新视角锐度**（自由漫游）：不填充的 B5，锐度 0.444；但 alpha p05 只有 0.189，大量视角露白。
- **折中**：sharpc1，alpha p05 0.722 / 锐度 0.409，是目前离双门槛最近的点。

**不要**把任何一个说成"通过了质量门"。当前双门槛（alpha p05 ≥ 0.70 且锐度 ≥ 0.42）**没有任何变体通过**，sharpc1 差 2.6%。
